# Datasheet — BdSLW60-SI and BdSLW401-SI (signer-independent pose benchmark)

Following *Datasheets for Datasets* (Gebru et al., 2021). This datasheet describes the **derived
artifacts we release** (MediaPipe pose tensors, labels, signer-disjoint split definitions,
metadata), not the source video datasets, which we do not redistribute.

**Anonymous version (for double-blind review).** Everything about the releasing authors is

## Motivation

- **Purpose.** Word-level Bangla Sign Language recognition is routinely reported near ceiling
  under random clip-level splits in which the same signer appears in train and test, so models
  can key on signer identity. We release fixed **signer-disjoint (SI)** protocols, plus
  leave-one-signer-out (LOSO) folds and matched-size signer-mixed splits, so that unseen-signer
  generalization and the Signer-Mixing Gap (SMG) can be measured reproducibly.
- **What the artifact exposes (paper values).** On BdSLW60 held-out TEST signers (2, 13), the
  eight shared-recipe pose architectures span **61.64–79.07 Top-1** (Adaptive GNN
  79.07 ± 0.89; §Main baselines, Table 1a). The SMG on matched-size random signer-mixed splits
  (n = 5) is **+29.41 pp** for BlockGCN (68.82 → 98.23) and **+19.90 pp** for Adaptive GNN
  (79.07 → 98.97) (§The Signer-Mixing Gap). A signer-clustered LOSO bootstrap over 11 unseen
  signers gives BlockGCN **74.37, 95% CI [64.72, 82.91]**, per-signer range 42.6–91.3
  (§The distribution over unseen signers). RGB VideoMAE on the same split reaches 80.93 ± 2.11.
- **Who created it.** The derived artifacts were created by the (anonymous) authors.

## Composition

| | BdSLW60-SI | BdSLW401-SI |
|---|---|---|
| Instances | per-clip pose sequence | per-clip pose sequence |
| Clips | 9,307 | 51,098 (front view) |
| Classes | 60 | 401 |
| Signers | 18 | 18 |
| Canonical split (clips) | train 5,748 / val 655 / test 1,365 + pretraining pool 1,539 | train 39,315 / val 3,950 / test 7,833 |
| Canonical split (signers) | train {1,4,5,6,8,9,11,12} / val {15} / test {2,13} / pool {3,7,10,14,16,17,18} | train: the 15 signers other than S04, S08, S15 / val {S15} / test {S04, S08} |
| Extra protocols | 11 LOSO folds; 5 matched-size signer-mixed splits (seeds 42–46) | the source's original split (seen-signer val); 1 signer-mixed split |
| Size on disk | 0.91 GB | 4.97 GB |

- **Instance format.** `data/<split>_data.npy`: float32 `(N, 3, 300, 27, 1)` = (clips,
  channels, frames, joints, persons). Channels are MediaPipe normalized image `x`, `y` and
  `visibility` (visibility is defined for the 7 body joints and is always 0 for the 20 hand
  joints). Clips are zero-padded to 300 frames; a body part that MediaPipe missed in a frame is
  zero. The 27 joints are 7 upper body (nose, shoulders, elbows, wrists) + 10 per hand (wrist,
  thumb tip, base and tip of the index, middle, ring and little fingers).
- **Labels and index.** `metadata/clips.csv` has one row per clip (`clip_id, split, signer_id,
  word_id, label, trial, pose_file, pose_row`) and `metadata/classes.csv` one row per class
  (`label, word_id, class_name`). `data/<split>_label.pkl` holds the same `(clip_ids, labels)`
  tuple for the training harness. The label is the source word id mapped to a contiguous 0-based
  index; there is no relabeling.
- **Pretraining pool (BdSLW60).** Signers {3,7,10,14,16,17,18} recorded only part of the
  vocabulary (38 of the 60 classes between them), so they are excluded from train/val/test and
  kept as an unlabeled pool for self-supervised pretraining. Their source labels are present in
  the files but no protocol uses them.
- **Is it a sample?** BdSLW60-SI contains every per-trial clip of the public segmented release
  (9,307 of 9,307 were processed). BdSLW401-SI contains the front-view clips of the public
  distribution; the lateral view described in the BdSLW401 paper is not in the public release.
- **Missing data.** Per-frame missed detections are zeros. A clip that fails extraction would
  be logged and excluded, never dropped silently; no extraction-failure markers exist for either
  dataset's pose cache.
- **Splits are signer-disjoint by construction.** `tools/build_p2_release.py` aborts on any
  signer or clip overlap between the canonical splits, and `tests/` guards the pretraining pool.
- **Sensitive data and re-identification risk.** The release contains no pixels, faces, names,
  or demographic fields, only skeleton trajectories and pseudonymous integer signer ids taken
  from the source filenames. **The poses are nevertheless not anonymous in a strong sense: body
  proportions and motion style are person-specific.** Our own leakage probe shows that signer
  identity is linearly recoverable from these poses: under a recording-grouped probe on held-out
  signers, the raw BdSLW60 pose features give class-conditioned **L_norm = 0.52–0.57** (trained
  encoders 0.23–0.35) and within-class **L_norm^wc = 0.96–0.98**; on BdSLW401 the earlier ungrouped
  protocol gives **L_norm = 0.63–0.72 (within-class 0.99)**, an upper bound (0 = chance,
  1 = perfect; §Signer decodability). Clips can therefore be linked to the same pseudonymous signer. Linking
  them to a real-world identity would additionally require reference recordings of that person.
  The terms of use (below) prohibit re-identification attempts.

## Collection process

- **We collected no new data and had no contact with participants.** The source videos were
  recorded, segmented and published by the source-dataset authors. BdSLW60 per-trial clips were
  obtained from the authors' public Kaggle distribution. BdSLW401 came from its public Kaggle
  distribution under an executed data use agreement (DUA) with the source owners.
- **Recording setup, dates, consent and ethics approval** were the responsibility of the source
  authors and are described in their publications (see Required citations).

- **Our processing.** MediaPipe Holistic (legacy `mp.solutions.holistic` API; `mediapipe==0.10.9`

  `preprocessing/generate_signer_split_npy.py`, `preprocessing/bundle_bdslw401_pose_to_npy.py`,
  `preprocessing/make_w401_sdval_bundle.py`, `preprocessing/generate_loso_split_bundle.py`).

## Preprocessing / cleaning / labeling

- 27-keypoint skeleton. Normalization and temporal windowing happen in the training feeder, not
  in the released tensors, which hold the raw MediaPipe coordinates.
- Bone-modality tensors are not shipped. They are a deterministic function of the joints
  (`preprocessing/generate_bone_data.py`).
- No relabeling; class = source word id.

## Uses

- **Intended.** Signer-independent isolated sign recognition benchmarking; Signer-Mixing Gap and
  signer-shortcut / leakage analysis; low-resource and cross-lingual pose self-supervised
  learning research; calibration and per-signer diagnostics.
- **Not validated for.** Continuous signing, translation, or deployment as an assistive or
  communication product (18 signers, one recording setup).
- **Prohibited / discouraged.** Commercial use; re-identification of, or attempts to contact,
  any signer; surveillance, military or biometric-identification use; other uses that the
  source owners' terms bar (DUA §4(g)); reporting signer-mixed (random-split) accuracy as a
  headline number.
- **Known biases.** Few signers: 11 with full coverage in BdSLW60, and in both datasets the
  canonical test set is 2 people and validation is 1 person. The source releases do not document
  signer demographics, so demographic balance cannot be audited. Single environment and front
  view. Hand keypoints are missing in a substantial fraction of frames, which can bias models
  toward body motion.
